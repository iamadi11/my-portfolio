# Whole-course acceptance

Use for a course-wide upgrade, not a routine wording change.

## Pilot, propagate, challenge

Inventory the actual ordered routes and prerequisite graph, including specialized legacy lessons and case studies. Map each objective to its state owner, source-backed rule, visible event, controllable counterexample and assessment. Mark missing coverage explicitly. Pick a demanding mechanism (partitioned consumption, cache freshness or replication failure) as the pilot; verify its boundaries and rendered interaction before reusing its architecture. Shared UI improvements do not establish all-topic accuracy.

Explore controls must alter a declared model input and observable outcome. Prefer a few independent, meaningful controls to inert breadth. Specify units, workload, capacity, ordering scope, failure timing and initial state. Predictions precede results; replay/reset uses the same inputs. Keep event traces inspectable without motion. For comparisons, state every changed assumption and distinguish caller uncertainty, rejection, transport loss and component failure.

Assess uses a new scenario, committed choices, explanation for each outcome and a fresh-attempt reset. Revisit links derive from the missed question's chapter; link directly to Explore. Self-assessed design decisions are labelled. No score or local history establishes mastery.

## Compact evidence matrix

One row per curriculum id: order, objective, prerequisites, mechanism/companions, experiment, assessment, source records, observed gaps and review state. Separate columns or statuses for:

- Structural checks: route, navigation, schema, source linkage and meaningful input variation.
- Executable checks: counterexample, boundary, invariants and agreement of film with model.
- Technical review: claim, exact primary source/section read, simplifications and unresolved discrepancies.
- Rendered acceptance: actual route/viewport/theme, keyboard and static playback, interaction/reset, labels/clipping.

Never infer the last two from a passing build or create identical "verified" rows by template. Reuse shared-renderer evidence with explicit scope; record chapter-specific evidence separately. Existing pinned sources can be reused as prior evidence without claiming they were reread.

## Delivery

Run deterministic checks and final production budgets after a coherent batch. Browser-review the pilot, representative families, the catalog and final chapter, then extend chapter-specific review across all ids. Record exact counts and remaining rows. Summarize skill changes, coverage, animation, source truth, themes, performance and tests in linked reports without duplicating evidence. Keep user-facing confidence proportional to completed evidence; learner benefit requires learner testing.
